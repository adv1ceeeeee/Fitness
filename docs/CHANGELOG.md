# Changelog

All notable changes are documented here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.0.0/)
Versioning: `MAJOR.MINOR.PATCH+BUILD`

- **MAJOR** — полный редизайн или несовместимые изменения БД
- **MINOR** — новая фича, видимая пользователю
- **PATCH** — баг-фикс, правка текста, мелкие улучшения

## [Unreleased] — 2026-05-11

### Added
- **Программы: копирование дней и упражнений** — в редакторе программы добавлены действия «Копировать»/«Вставить» для дня и отдельная вставка скопированного упражнения; вставка пропускает упражнения, которые уже есть в выбранном дне.
- **Программы: прогресс по неделям цикла** — вкладка `Прогресс` в окне упражнения показывает недели цикла, подсвечивает текущую неделю и позволяет записывать рабочий вес на каждую неделю.
- **Дроп-сеты: отдельный вес** — для дроп-сета хранится и отображается второй недельный вес (`drop_set_weekly_target_weights`); в карточке и окне редактирования показываются основной вес и вес дроп-сета.
- **Описание упражнения** — окно редактирования разделено на вкладки `Описание` и `Прогресс`; во вкладке описания показываются картинка/GIF и русское описание техники.
- **Профиль: экраны настроек** — настройки профиля переделаны из раскрывающихся секций в отдельные вложенные экраны в стиле Android/iOS: строка настроек открывает свой экран с доступными действиями.
- **Русские описания техники** — добавлен backfill стандартных описаний упражнений в `description_ru`.
- **Каталог упражнений: локальный fallback** — если Supabase не отвечает на Android, экран добавления упражнений показывает встроенный локальный каталог из стандартных программ, а сеть используется для последующего уточнения настоящих `exercise_id`.
- **Android APK: стабильная подпись** — release APK собирается одним и тем же keystore, поэтому новые сборки ставятся поверх старых без удаления приложения.
- **Программы: изменение порядка упражнений** — добавленные в программу упражнения можно зажать долгим нажатием и перетащить вверх/вниз без отдельной кнопки-перетаскивания.

### Changed
- **Карточка упражнения в программе** — название выделено синим, параметры подходов/повторов/веса — фиолетовым; удалён drag-handle, вместо него используется кнопка изменения.
- **Вес в карточке** — показывается вес текущей недели; если он не заполнен, используется ближайший предыдущий недельный вес, затем обычный целевой вес.
- **Начать тренировку** — сохранённый подход обновляет лучший вес текущей недели, чтобы ручная запись и запись через тренировку сходились в одну историю.
- **Загрузка программы** — экран программы больше не делает принудительный сетевой refresh при каждом открытии; сначала используются кэши, чтобы секции и дни не пропадали при медленной сети.
- **Каталог упражнений** — основной список теперь запрашивает только легкие поля (`id`, названия, категория, картинки), а избранное и подробные описания догружаются отдельно.
- **Порядок упражнений** — после перетаскивания локальный список сразу получает новые значения `order`, а порядок сохраняется в кэш и Supabase.
- **Запуск тренировки с центральной кнопки** — экран сессии открывается в две фазы: сначала обязательные данные тренировки и упражнений, затем история, PR, медиа и рекомендации догружаются фоном.
- **Сохранение итогов тренировки** — запись подходов и завершение сессии получили таймауты и fallback на прямое обновление `training_sessions`, чтобы кнопка сохранения не висела бесконечно при медленном RPC.

### Fixed
- **Суперсеты** — повторное нажатие на связку теперь развязывает упражнения без «залипшего» одиночного элемента.
- **Дроп-сеты** — второй вес больше не вычисляется только как 60% основного, если пользователь записал отдельный вес дроп-сета.
- **Обновление упражнения** — частичные обновления больше не затирают вес, длительность и RPE, когда меняется только дроп-сет или суперсет.
- **Сортировка упражнений** — исправлено переполнение в bottom sheet сортировки.
- **Android: открытие программ** — исправлена нестабильность, когда мультисекционная программа при повторном входе показывала только одну секцию/день из-за таймаута загрузки остальных секций.
- **Android: PostgREST `movement_type`** — убраны обращения к колонкам `movement_type`, `difficulty`, `equipment_type`, `input_mode` из запросов к `exercises`, пока эти колонки не применены в production БД.
- **Android: пустой каталог упражнений** — таймаут каталога больше не оставляет экран без списка упражнений; используется кэш или локальный fallback.
- **Порядок упражнений после перезахода** — новый порядок больше не сбрасывается при повторном открытии программы, даже если сеть отвечает медленно.
- **Тренировка на сегодня: русские названия** — список теперь использует `displayName`, поэтому `name_ru` показывается вместо английского `name`, когда перевод есть.
- **Тренировка на сегодня: порядок упражнений** — локальный кэш сегодняшней тренировки версионирован и очищается после перетаскивания, поэтому старый порядок больше не возвращается из файла кэша.

### Database
- `058_backfill_description_ru.sql` — заполняет `description_ru` для стандартных упражнений.
- `059_workout_exercise_weekly_weights.sql` — добавляет `weekly_target_weights` и `drop_set_weekly_target_weights` в `workout_exercises`.
- `060_exercise_catalog_indexes.sql` — добавляет индексы для быстрых запросов каталога стандартных и пользовательских упражнений.

## [1.8.0+22] — 2026-03-28

### Added
- **RecSys: продвинутая прогрессия** (`evaluateProgression`) — единая функция заменила разрозненные сигналы: 7 условий приоритетом, 1RM PR-сигнал (Эпли ±3%), цель-зависимые пороги (strength vs weight_loss/endurance), поддержка bodyweight-упражнений, RPE-калибровка через персональный медианный RPE (clamp −2…+2)
- **RecSys: энергетическая модель** — `energy_end` сохраняется в `training_sessions` после каждой сессии; межсессионное восстановление по формуле `E = 100 − (100 − E_end) × exp(−Δt × wellnessMod / (τ × expMod))`; τ=24/36/48ч в зависимости от интенсивности; 10 бакетов готовности
- **RecSys: внутрисессионная усталость** (`evaluateFatigue`) — суперсеты получают drain × 1.2; warm-up подходы (`is_warmup=true`) исключены из расчёта
- **RecSys: дилоад** (`evaluateDeload`) — показывается первой карточкой инсайтов при объёме ≥10% выше нормы × ≥3 нед. подряд
- **RecSys: тренд объёма мышц** — инсайт при падении >20% за последние 4 нед. vs предыдущие 4 нед. (8-недельное окно, `getMuscleGroupVolumeTrend()`)
- **RecSys: частота нагрузки** — предупреждение при интервале <2 дней на группу мышц (`getAvgDaysBetweenSessionsByMuscle()`, TTL 2ч)
- **RecSys: корреляция сон→результаты** (`evaluateWellnessCorrelation`) — сравнение среднего веса в «хорошие» (sleep >7ч) vs «плохие» (sleep <6ч) дни; порог показа: разница >5%
- **RecSys: дисбаланс мышц** (`evaluateMuscleBalance`) — расширены антагонист-пары: добавлены legs:quad↔legs:hamstring и shoulders:push↔shoulders:rear; суб-категории определяются динамически из `movement_type` + имени без изменений БД
- **RecSys: ranking инсайтов** — поле `confidence` (0–1) у каждой карточки; сортировка по убыванию перед отображением
- **RPE-калибровка** — `getRpeCalibrationOffset()` (TTL 6ч): медиана RPE пользователя из последних 20 сессий; применяется к порогам прогрессии
- **Средний отдых** — `getAvgRestSeconds(exerciseId)` (TTL 30 мин); подсказка «Обычно вы отдыхаете X:XX» на экране отдыха
- **1RM из personal_records** — `getPersonalBest1RMForExercises()` (TTL 30 мин): батч-запрос к `personal_records`, возвращает лучший расчётный 1RM за всю историю
- **Neon UI: прогресс-бар** — `_NeonProgressPainter` (CustomPainter + `MaskFilter.blur`) вместо `LinearProgressIndicator`
- **Neon UI: таймер отдыха** — `BoxDecoration(shape: BoxShape.circle, boxShadow: [...])` с нарастающим свечением при завершении таймера
- **Neon UI: PR-баннер** — 3-слойный `boxShadow` (белый core + ярко-зелёный + широкий ambient)
- **Neon UI: карточка готовности** (`_EnergyReadinessCard`) — `boxShadow` с цветом энергетического уровня (зелёный/оранжевый/красный, `alpha: 0.22`)
- **Миграция `053_energy_end.sql`** — добавляет колонку `energy_end double precision` в `training_sessions`
- **Контекст веса тела в инсайтах** — если вес снизился >2 кг за период, добавляется примечание о возможном влиянии

### Fixed
- **Warm-up фильтр** — `_fetchLastSetsForExercises()` теперь добавляет `.eq('is_warmup', false)`, исключая разминочные подходы из расчёта прогрессии

### Technical
- `recsys_service.dart`: унифицирован `evaluateProgression()` — параметры `personalBest1RMKg`, `userGoal`, `rpeCalibrationOffset`, `isBodyweight`, `inSuperset`; `estimatedOneRepMax(weight, reps)` (Эпли); `evaluateFatigue()` с supertset 1.2× drain
- `analytics_service.dart`: `getPersonalBest1RMForExercises()`, `getRpeCalibrationOffset()`, `getMuscleGroupVolumeTrend()`, `getAvgDaysBetweenSessionsByMuscle()`, `getAvgRestSeconds()` — все в `AppCache`
- `workout_session_screen.dart`: загружает `_personalBests1RM`, `_userGoal`, `_rpeCalibrationOffset`, `_avgRestByExercise`; передаёт в оба вызова `evaluateProgression()`; `_saveExerciseToHistory()` пишет `inSuperset`; `_NeonProgressPainter` класс
