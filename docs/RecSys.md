# RecSys — Рекомендательная система

Документ фиксирует архитектуру, текущую реализацию и план развития
рекомендательной системы SportWAI.

> Обновлён: 2026-03-28

---

## Философия

Пользователь воспринимает систему как «умную» не из-за сложности алгоритма,
а из-за **специфичности и объяснения**. Рекомендация должна:

1. Называть **конкретные цифры** из данных пользователя
2. Давать **причину** («потому что…», «замечено что…»)
3. Появляться **в нужный момент** (перед тренировкой, после, в инсайтах)

Сравни:
- ❌ «Рекомендуем снизить нагрузку сегодня»
- ✅ «Вчера ты спал 5ч и стресс 8/10 — тяжёлую тренировку лучше перенести»

---

## Архитектура

Весь RecSys — **чистые функции** в `lib/services/recsys_service.dart`.
Нет зависимостей от Flutter, Supabase или IO — полностью тестируемы.
Данные загружает `AnalyticsService`, передаёт в функции, результат рендерит UI.

```
AnalyticsService          recsys_service.dart          UI
─────────────────    →    ──────────────────────    →   ────────────────
getEnergyState()          computeEnergyStart()           _EnergyReadinessCard
getLastSets()             evaluateProgression()          _ProgressionChip
getDeloadMetrics()        evaluateDeload()                _InsightCard
getMuscleBalance()        evaluateMuscleBalance()        _InsightCard
getStagnantExercises()    evaluatePlateau()              _InsightCard
getRpeCalibration()       evaluateWellness()             _WellnessRecBanner
…                         evaluateFatigue()              _FatigueWarning
```

## Реализованные эвристики

### 1. Велнес → управление нагрузкой (`evaluateWellness`)

**Где:** баннер на главном экране перед тренировкой.

| Условие | Рекомендация |
|---------|--------------|
| `sleep < 6` или `sleep_quality ≤ 2` | Предупреждение: лёгкий день |
| `stress ≥ 8` | Снизить интенсивность |
| `energy ≤ 3` | Убрать тяжёлые компаунды |
| `soreness ≥ 4` | Не тренировать болезненную группу |
| Три и более факторов | Рекомендация полного отдыха |

---

### 2. Прогрессия весов (`evaluateProgression`)

**Где:** внутри сессии при открытии упражнения.

Сигналы (в порядке приоритета):

| # | Условие | Направление |
|---|---------|-------------|
| 0 | Энергия bucket 9–10 | Decrease (форс) |
| 1 | Reps < target | Maintain |
| 2 | RPE ≥ 9 два раза подряд | Decrease |
| 3 | N сессий подряд все повторения (N=2 для strength, N=3 иначе) | Increase |
| 4 | RPE ≤ 7 обе сессии + все повторения | Increase |
| 5 | RPE ≤ threshold одна сессия + все повторения | Increase |
| 6 | Повторения ≥ верхней границы диапазона | Increase (слабый) |

**Дополнительные факторы:**
- **1RM PR** — если предложенный вес выведет расчётный 1RM (Эпли) на уровень личного рекорда ±3%, к сообщению добавляется «Это будет личный рекорд!»
- **Энергия bucket 7–8** — Increase → Maintain, добавляется пояснение
- **Энергия bucket 5–6** — Increase сохраняется, добавляется осторожное примечание
- **RPE-калибровка** — пороги сдвигаются на `rpeCalibrationOffset` (персональный отклонение от медианы RPE=7)
- **Goal-aware** — `strength`: threshold 2 сессии / RPE ≤ 7; `weight_loss`/`endurance`: только сильный сигнал
- **Bodyweight** — отдельная ветка: нет рекомендаций по весу, прогрессия через повторения
- **Суперсеты** — упражнения в суперсете получают 1.2× drain в модели усталости

---

### 3. Дисбаланс групп мышц (`evaluateMuscleBalance`)

**Где:** инсайт в аналитике.

Отслеживаемые антагонист-пары:
- Грудь ↔ Спина
- Квадрицепс ↔ Бицепс бедра (`legs:quad` ↔ `legs:hamstring`)
- Передние дельты ↔ Задние дельты (`shoulders:push` ↔ `shoulders:rear`)

Суб-категории (`legs:quad`, `legs:hamstring`, `shoulders:push`, `shoulders:rear`)
определяются динамически из `movement_type` + имени упражнения без изменений БД.

---

### 4. Детекция застоя — плато (`evaluatePlateau`)

**Где:** инсайт в аналитике.

Триггер: упражнение не прогрессирует по весу ≥ 3 недель при регулярных тренировках.

---

### 5. Корреляция велнес → результаты (`evaluateWellnessCorrelation`)

**Где:** инсайт в аналитике (требует ≥ 20 сессий).

Сравнивает средний вес на упражнениях в «хорошие» дни (sleep > 7ч) vs «плохие» (sleep < 6ч).
Показывается только если разница > 5%.

---

### 6. Контекстные инсайты после тренировки

**Где:** экран итогов сессии.

Примеры: «Лучшая сессия за 3 недели», «Ноги: +15% к объёму», «18 тренировок подряд».

---

### 7. Рекомендация дилоада (`evaluateDeload`)

**Где:** инсайт в аналитике (появляется первым при срабатывании).

Триггер: объём нагрузки ≥ 10% выше персональной нормы И ≥ 3 недели подряд.

```
DeloadRec {
  overloadPct: double        // процент превышения
  weeksAboveBaseline: int    // количество недель
  message: String
}
```

---

### 8. Внутрисессионная усталость (`evaluateFatigue`)

**Где:** показывается при переходе к упражнению на ту же группу мышц.

Модель: диффузия энергии через сессию с гауссовским шумом (σ=0.025 за подход).
Drain-фактор зависит от `movementType` и `equipmentType`.
Warm-up подходы (`is_warmup = true`) пропускаются.
Упражнения в суперсете — drain × 1.2.

---

### 9. Тренд объёма по группам мышц

**Где:** инсайт в аналитике (8-недельное окно).

Сравнивает объём последних 4 недель с предыдущими 4 неделями по каждой группе.
Инсайт при падении > 20%: «За последние 4 недели объём на X упал на Y%».

---

### 10. Частота нагрузки по группам мышц

**Где:** инсайт в аналитике.

Вычисляет средний интервал между сессиями по каждой мышечной группе за 8 недель.
Предупреждение при интервале < 2 дней: «Слишком частые нагрузки на X».

## Энергетическая модель (межсессионная)

Ключевая особенность: энергия **не начинается с 100 каждую тренировку**.
Она вычисляется от последней зафиксированной точки (`energy_end` в `training_sessions`).

### Формула восстановления

```
E_start = 100 − (100 − E_end) × exp(−Δt × wellnessMod / (τ × expMod))
```

| Параметр | Значение |
|----------|----------|
| `E_end` | Энергия в конце последней сессии (0–100) |
| `Δt` | Часов с последней тренировки |
| `τ` | Константа восстановления: 24ч (лёгкая/кардио), 36ч (средняя), 48ч (тяжёлая) |
| `expMod` | 1.2 (< 6 мес), 1.0 (6–24 мес), 0.85 (> 24 мес) |
| `wellnessMod` | 0.8–1.1 в зависимости от сна/стресса/энергии |

### Шкала 10 бакетов

| Бакет | Reserve | Метка |
|-------|---------|-------|
| 1–2 | 90–100% | Пик |
| 3–4 | 70–89% | Хорошо |
| 5–6 | 50–69% | Умеренно |
| 7–8 | 30–49% | Низко |
| 9–10 | 0–29% | Истощён |

`energy_end` сохраняется в `training_sessions` после каждой сессии.

## 1RM — расчётный максимум (Эпли)

```dart
1RM = weight × (1 + reps / 30)     // reps 1–30
```

Используется для сравнения результатов через разные диапазоны повторений.
`getPersonalBest1RMForExercises()` возвращает лучший 1RM за всю историю из `personal_records`.

## RPE-калибровка

Каждый пользователь оценивает нагрузку по-разному. Медиана RPE 7.0 = «нормальный» уровень.

```
offset = clamp(medianUserRpe − 7.0, −2.0, +2.0)
calibratedRpe = reportedRpe − offset
```

Калибровка применяется к порогам прогрессии. Загружается с TTL 6ч.

## Confidence ranking инсайтов

Каждая карточка `_InsightCard` имеет поле `confidence` (0.0–1.0).
Карточки сортируются по убыванию confidence перед отображением.

| Инсайт | Confidence |
|--------|-----------|
| Дилоад (≥5 недель данных) | 0.9 |
| Тренд объёма (8 недель) | 0.85 |
| Дисбаланс мышц (30 дней) | 0.8 |
| Частота нагрузки | 0.7 |
| Застой / плато | 0.75 |
| Тренд по группе | 0.75 |
| Корреляция велнес | 0.7 |
| Лучший день недели | 0.6 |
| Сравнение с сообществом | 0.5 |

## Кеширование

Все методы `AnalyticsService` используют `AppCache` (SharedPreferences + TTL):

| Метод | TTL |
|-------|-----|
| `getEnergyState()` | 30 мин |
| `getPersonalBest1RMForExercises()` | 30 мин |
| `getRpeCalibrationOffset()` | 6 ч |
| `getDeloadMetrics()` | 1 ч |
| `getMuscleGroupVolumeTrend()` | 20 мин |
| `getAvgRestSeconds()` | 30 мин |
| `getAvgDaysBetweenSessionsByMuscle()` | 2 ч |

Кеш инвалидируется при `invalidateStatsCache()` (после сохранения сета, смены цели и т.д.).
